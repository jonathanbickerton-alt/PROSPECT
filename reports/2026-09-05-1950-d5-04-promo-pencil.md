## The decision, recorded before code

`EXPECTED.md`, commit `3995aa0`, beside the 1903 measurements: **option 1 — the
Volume table's pencil on a promotion-built row routes to the Promotion card's
own editor; the Volume form is never opened for a promotion-built row.**

The reason is recorded from the measurements rather than from taste: the Volume
form has no mix, no per-band rate, no lock set and no pricing arm, and a
no-change save from it **zeroed the baked rate** (`arpu` 36 → 0). An editor
that cannot show what it is editing drops it silently, and it did.

Also recorded: **the row stays listed in the Volume table.** Option 1 changes
where the pencil goes, not what the table shows — deliberately not option 2,
because a user who can see a row should be able to act on it from where they
see it.

### One decision point, not a branch per pencil

```ts
const editEventFromVolumeTable = useCallback((event: MarketEvent) => {
  if (event.isPromotion) {
    setActiveTab('promotion');
    handleEditPromoStart(event);
    return;
  }
  handleEditStart(event);
}, [handleEditPromoStart, handleEditStart]);
```

Both Volume pencils route through this pair, so "which editor owns a promotion"
is answered in one place and a third pencil cannot answer it differently.

**The tab is switched first.** Seeding the promotion draft while the Volume card
is on screen would leave the user looking at an unchanged form with an invisible
edit in progress.

### The campaign pencil did not exist — measured

The brief asks the campaign pencil to route the same way. It had nothing to
route: `campaignGroups` is built from **non-promotion** rows, so a promotion
row's lookup returned `undefined`, `group?.editable` was falsy, and the pill
rendered as a **disabled span** — `cursor-not-allowed`, and with `group?.reason`
also undefined it stated **no reason at all**. A control a user can see, cannot
press, and is told nothing about.

Under option 1 the promotion card's group owns it, so the row now reads
`promoCampaignGroups` and the pill is a working pencil that routes. That is a
control becoming enabled, not merely re-pointed, and it is stated here rather
than slipped in: leaving a dead pill beside a working row pencil would be
incoherent with the decision.

### Mounted, driven from the Volume tab

**Both writers are captured, and that is the discriminator.** The Volume form
commits through `setMarketEvents`; the Promotion editor through
`updateMarketEvent`. Which one fires says which editor took the row, without
spying on a handler — `via Volume 0` **is** the assertion that `handleEditStart`
was not called for a promotion.

The 23-field engine read-set is **identical before and after**, `arpu` included.
The 1903 deep-equal now passes, which is what the decision claims.

### Two fixture faults of mine, both measured rather than guessed

The first run reported `via Promotion 0` and no mix rows. Neither was the route:

1. `computeTierData` returns `[]` unless a **revenue or ARPU column** is named
   (its first line), and the shared props pass `''` for both — so no fixture
   mounted through them can produce tiers at all. **The columns, not the rows.**
2. With the mix arm on and zero tiers, **Save Changes is correctly disabled**
   (`promoMixEnabled && promoTierData.length === 0`). The card was refusing to
   save a mix it could not populate — right behaviour, and my drive read it as
   a broken route.

Fixed by giving this one mount Retention rows carrying real value tiers and an
ARPU column. The shared fixture is untouched.

## Limits of this check

- **The campaign route is built but not driven.** The row pencil is exercised
  end to end; the campaign pill's route is asserted by neither a mounted click
  nor a trap. It shares `editCampaignFromVolumeTable` with nothing else, so
  nothing would catch it breaking.
- **One promotion shape.** Percentage, Retention, value mix, one lock, no
  pricing arm and no spread. A promotion carrying a dilution arm is reasoned
  from the same read-set, not driven.
- **The tab assertion reads a class name.** `bg-white` on the tab button is the
  active style; a restyle would break the check without breaking the behaviour.
- **`via Volume 0` is a proxy for "handleEditStart was not called."** It is a
  strong one — that handler's only commit path is `setMarketEvents` — but it is
  an observation of the writer, not of the call.
- **No walk, no browser.** Everything is the mounted card on constructed
  fixtures.
