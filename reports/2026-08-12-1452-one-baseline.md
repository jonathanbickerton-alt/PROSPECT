## 2. The fix is a shared object, not a matching formula

`effectiveTierArpuMap` is built **once** from `effectiveTierArpu` across the
tiers. The card's baseline averages that map; the construction site spreads it
into `tariffBaseArpu`.

**That distinction is the whole point.** The divergence did not arise because
two formulas disagreed — both were an equal-weight mean. It arose because each
walked `yieldTierData` separately and they came to read *different rates*: the
card the derived ones, the snapshot the effective ones after `4d8ae2b` changed
it. **Two computations that agree today drift tomorrow; one object cannot.**

So the guard is not "the numbers match" but "both read the same object", and the
spec asserts exactly that — plus that no baseline over the derived rates
survives anywhere, since bypassing the old computation is not the same as
removing it.

## 3. No override, no change — asserted, not assumed

With an empty override map the effective rate **is** the derived rate, so the
equal-weight mean over either is the same number. The spec asserts this
**exactly**, with `Object.is`, rather than within a tolerance.

Every shipped fixture is that case — none carries a tier override — which is why
no figure moves. That is the mechanism stated, not merely the observation that
the suite stayed green.

The complementary assertion matters as much: a stated rate **does** move the
baseline, and a stated **zero** moves it too. If those did not hold, the card and
the forecast would still disagree and the fix would be cosmetic.

## 4. The caption

Was: *"Equal-weight avg of tier ARPUs"* — which became ambiguous the moment
"tier ARPUs" could mean derived or stated.

Now: *"Equal-weight average of the stated tier ARPUs — the same basis the
forecast applies."* Six locales, replacing the existing key rather than adding
one.

**A baseline that moves when you edit an override needs to read as design.**
Without the caption it reads as instability.
