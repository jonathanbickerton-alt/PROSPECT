**The generator**, `WhatIfTab.tsx:4035-4049` — the volume spread on the Add
path:

```ts

  const vol = Math.round((newEvent.subscriberVolume || 0) * fraction);
```

Three lines decide it:

- `const fraction = pct / total;` — the shares are **normalised to sum to 1**;
- `vol = (newEvent.subscriberVolume || 0) * fraction` — so the entered figure
  is a **TOTAL DISTRIBUTED ACROSS** the months, not a level reached by them;
- `pcts.map(...)` — the array is **exactly `spreadMonths` long**, so emission
  **stops** at month N. Nothing is held after it.

For 2,500 over 3 months the build emits **833 / 833 / 834**, summing to 2,500,
then nothing. The addendum's Hold-ON reading is **833 / 1,667 / 2,500, then
2,500 held** — a different figure in every month, and an unbounded tail. The
build is neither that nor the held-split alternative (10 / 10 / 10 then 10):
it is a third thing, a share split that terminates.

`buildPromoEvents` uses the identical construction at `:634-639`
(`const pcts = p.spreadEnabled ? ... : [100];` then the same `total`), so the
Promotion card behaves the same way. This is the same reading the 0705 report
recorded as *"the spread emits ONE ROW PER MONTH, then stops"*.

**The linear-cumulative shape the addendum names does exist — on churn only.**
`churnFold.ts:172-176`:

```ts
export function linearChurnRamp(targetPct: number, months: number): number[] {
  const n = Math.max(1, Math.floor(months) || 1);
  const t = Number.isFinite(targetPct) ? targetPct : 0;
  return Array.from({ length: n }, (_, i) => (t * (i + 1)) / n);
}
```
