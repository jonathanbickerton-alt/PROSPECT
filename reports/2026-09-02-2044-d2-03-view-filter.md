## Item 1 — measure, read-only

### (a) The sites that filter market events by view

**Exactly one**, and it is not the engine: `WhatIfTab.tsx:965`, inside
`computeAdjustedForecast`, an INLINE REIMPLEMENTATION of the shared predicate.
`marketEvents` arrives from App whole (`App.tsx:4602`); nothing upstream
filters it.

The predicate as it stood, verbatim:

```ts
const segMatch  = e.segment === 'All' || vseg === 'All' || e.segment === vseg;
const prodL1Match = e.product === 'All' || !vprodL1 || e.product === vprodL1;
const prodL2Match = !e.productL2 || e.productL2 === 'All' || !vprodL2 || e.productL2 === vprodL2;
const chanL1Match = e.channel === 'All' || !vchanL1 || e.channel === vchanL1;
const chanL2Match = !e.channelL2 || e.channelL2 === 'All' || !vchanL2 || e.channelL2 === vchanL2;
const tarL1Match = !e.tariffL1 || e.tariffL1 === 'All' || !vtarL1 || e.tariffL1 === vtarL1;
const tarL2Match = !e.tariffL2 || e.tariffL2 === 'All' || !vtarL2 || e.tariffL2 === vtarL2;
```

The shared definition it duplicates is `eventScopeMatchesView`
(`forecasting.ts:512`), whose own doc states the intersection rule the brief
specifies — and states it correctly:

```ts
const ok = (dim: string | undefined, view: string | null) =>
  !dim || dim === 'All' || !view || view === 'All' || dim === view;
```

**Truth table**, measured for the save's stored event
(Large Enterprise / Mobile Voice / All / All / All / All, Inflow, 2026-09):

| view | inline `:965` | `eventScopeMatchesView` |
|---|---|---|
| All — cohort dims = string `'All'` (what the APP builds) | **false** | true |
| All — cohort dims = `null` (what 1634 passed) | true | true |
| Large Enterprise / All | **false** | true |
| Large Enterprise / Mobile Voice | true | true |
| SME / All (disjoint) | false | false |

The failing dimension is `prodL1Match` in every disagreeing row.

**THE MECHANISM: "All" HAS TWO REPRESENTATIONS AND THE COPY KNEW ONE.** The
copy tests the view side with `!vprodL1`, so only `null` counts as All. But
`cohortScope` (`WhatIfTab.tsx:2331`) maps `baseForecast.cohort.product ?? null`,
and `??` converts only nullish — a cohort whose product is the STRING `'All'`
stays `'All'`, which is truthy. So `!vprodL1` is false, `'Mobile Voice' !== 'All'`,
and the event is withheld.

Segment alone escapes, because its clause carries an explicit `vseg === 'All'`
string test. The other six dimensions do not. Every one of them has the same
latent defect; product L1 is simply the one this event exercised.

**This also answers what the app passes that 1634 did not.** 1634 handed the
engine `null` dims and measured 8,000.00 at All. The app hands it the literal
`'All'`. The engine was never wrong — the event never reached it.

## Item 2 — the fix

The inline copy is **deleted, not repaired**, and the apply path now calls
`eventScopeMatchesView` with the `viewScopeForMatch` already built above it.

Repairing it would have meant adding `|| vprodL1 === 'All'` six times — correct
numbers, and a second definition of the rule left standing. That is how two
implementations that agree today become the two that disagree tomorrow, and
this defect IS that failure already run to completion: the tooltip called the
shared predicate and the apply path did not, so the card contradicted itself on
screen.

Weighting is untouched and still happens after applicability: `eventShare` for
absolute events, `forecastCoverage` with the `eventCoverage` fallback for
percentages. Nothing was folded into the predicate.

## Item 3 — the three surfaces agree

**Measured, not built** — the brief's own instruction where the tooltip is more
than one site.

After the fix the tooltip's market-event carrier and the engine call THE SAME
FUNCTION against the SAME scope (`tipView` and `viewScopeForMatch` are both
built from `cohortScope`), so caption, expander and tooltip agree by
construction rather than by coincidence.

Pointing the tooltip at `appliedEventIds` was considered and **not done**, for
a reason worth recording: EVENTS THIS MONTH is **three carriers** — market
(`:2399`), yield (`:2404`) and pricing (`:2408`) — and `appliedEventIds` covers
market events only. Repointing one carrier would leave the block internally
inconsistent, one third of it answering a different question from the other two.

One residual difference stands and is a finding, not a defect: `appliedEventIds`
is pushed unconditionally for every applicable event, so an event that matches
the view but lands on no populated leaf is counted by the caption and listed by
the tooltip while moving nothing. That is the shed item from 1634, still open.

## Item 4 — the mounted spec

`scripts/view-apply-mounted-spec.tsx`, `npm run spec:view-apply-mounted`, **18
checks**.

**Why this class of check was missing, and what it changes.** Three sessions
measured this defect and none reproduced it, because every check handed
`computeAdjustedForecast` the event directly. Done that way the engine is
correct. A spec that calls the engine cannot see a filter in front of the
engine. This one mounts the card and reads the rendered KPI, which is the only
position from which "the event never arrived" and "the engine mishandled it"
look different.

Fixture: two leaves, Corporate/Mobile Voice and Corporate/Broadband, with the
historical and forecast mixes deliberately DIFFERENT — history 300/700, forecast
200/800. That difference is asserted as check 0, before anything is concluded
from it. The views resolve through the real `resolveFromStore` over a two-leaf
store, and each view is asserted to resolve at all, because a null forecast
renders no KPI card and every delta below would read NaN and pass vacuously.

Measured, absolute +1,000 event scoped to the Mobile Voice leaf:

```
leaf 1000    All 1000    Corporate/All 1000    disjoint leaf 0
```

Percentage +10% on the same scope:

```
leaf 20      All 20                            disjoint leaf 0
```

The percentage case is the discriminating one: the forecast mix gives
200/1000 = 0.2 and therefore 20 at All, matching the leaf to the penny. The
HISTORICAL mix would give 300/1000 = 0.3 and therefore 30. So this fixture
catches a regression to history-weighting as well as the withholding bug.

Selectors are testids throughout — `impact-base-delta` and `impact-event-count`
were added to the KPI card for it. The labels beside them are translated, so a
text selector would be a locale bomb: green in en, red in de.
