## Item 1 — the spec

`scripts/ai-hold-spec.ts`, `npm run spec:ai-hold`, 13 checks.

**The pattern list, quoted exact**, is seven regexes:

```
/@google\/genai/            /\bGoogleGenAI\b/        /\bgenerateContent\b/
/\bGEMINI_API_KEY\b/        /\bfrom\s+['"]openai['"]/
/\bfrom\s+['"]@anthropic-ai\//                       /\bapi[_-]key\b/i
```

Every alternative is a package specifier, an exported SDK symbol, or a key
name — each containing a character (`@`, `/`, `_`) or a capitalisation that
ordinary camelCase cannot produce by accident. `api[_-]key` requires the
separator deliberately: bare `apikey` would match `rapidApiKeyed`-shaped
names, and the separator is what makes it a key pattern rather than a
substring. There is **no bare `LLM`** — that was 1230's false positive, and it
is now a *test case inside the spec* rather than a lesson in a report:

- the list must **bite** on a known-positive sample (5 of 7 must match), so a
  list that matches nothing cannot pass on any tree;
- and must **not** match `generateAllMissingForecasts` or
  `showAcceptAllModal`, the two identifiers it wrongly flagged.

**The four checks:**

## Item 2 — the two traps

Both planted by hand against an md5 taken before the plant, landing confirmed
by the hash changing, restoration confirmed by it returning.

| trap | file | FAIL line |
|---|---|---|
| 172 | `package.json` | `(a) package.json declares no @google/genai [an AI SDK dependency is the first of §33's three criteria]` |
| 173 | `.env.example` | `(d) the three AI identifiers appear in ZERO tracked files [.env.example :: GEMINI_API_KEY]` |

Two rather than one because the hold has two independent surfaces — the
**dependency** (what npm installs and the bundler can reach) and the **key**
(what a tracked file hands an operator) — and a single trap could not say
which had failed. The branch declared both and wired neither, so these two are
the whole of what ever existed to guard.

### What trap 172 found, which is the session's real finding

Trap 172's first run reported **two** failures, and the second one was not the
trap:

```
FAIL  (d) … [package.json :: @google/genai | scripts/guard-traps.ts :: @google/genai
            | scripts/guard-traps.ts :: GEMINI_API_KEY]
```

Adding the traps had put the identifiers into `guard-traps.ts` as their
planted mutation text — so **the spec was red on a clean tree**, and the trap
that proves the guard bites had made the guard bite on itself. It passed
13/13 before the traps existed and would have failed the gate immediately
after.

`guard-traps.ts` therefore joins the stated exclusions, alongside the spec
itself, `EXPECTED.md`, `reports/`, the working agreement and
`regression-guard.md` — every one a file whose *job* is to carry these
strings. The exclusion is safe rather than a hole because none of them ships:
each is a script, a record, or a prompt file, and the bundler reaches none of
them. All of `src/`, both manifests, and every other tracked file stay in
scope. This is the same class as the known `spec:survival` issue where quoted
anchor text counts as a first-row dereference.

Re-verified after the exclusion: trap 172 still catches, and its FAIL now
names only `package.json`.

its wording updated to name the spec and the advisory.

**The working agreement §6** — `(queued)` → `(spec:ai-hold, 4926717)`, plus

**`README.md:278` — NOT removed, and this corrects my own 1230 finding.**

1230 recorded that line as stale documentation referencing an absent
`metadata.json`. That was wrong. The block it sits in is headed
`## Archive Folder` and documents the contents of `_archive/` — and

## Limits

- **Python could not be run in this session.** Every `python` invocation hung
  at startup and was killed; the tree was checked after each and no write had
  landed. The by-hand plants were done in bash with `md5sum` instead, which is
  why the trap evidence is hashes rather than the usual sha1 script output.
- **The advisory walk is bounded** — depth 6, two roots (`_archive`,
  `.claude/worktrees`), and a file-extension filter. Other gitignored copies
  outside those roots would not be listed.
- **`spec:ai-hold` asserts the declaration surface only**, which is all that
  ever existed on the branch. If AI capability were ever added *and wired*, the
  `src/` pattern check (b) is what would have to catch the call site, and it
  has been verified to bite only against a synthetic sample, not against a real
  one — there has never been a real call site in this repo to test it on.
