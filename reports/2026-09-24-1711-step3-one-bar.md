### The gate (clause 4) — `showAdjusted`, defined once in FVA below `viewSeam`

The gate opens only when all of these hold:

- the context has an adjusted forecast;
- `makeForecastKey(adjusted.base.cohort…) === viewSeam.key`, i.e. it was built
  for exactly the view on screen;
- at least one event in `adjusted.marketEvents` is on (`isEventOn`) and matches
  the view (`eventScopeMatchesView`). The event-to-dimension mapping is the
  existing one WhatIfTab's tooltip uses, so there is no new predicate.

**Readers.** The badge (`data-testid="adjusted-badge"`) and the toggle
(`data-testid="adjusted-toggle"`) both render only while the gate is open, with
no disabled state.

**Forced off.** `adjustedScoringOn = useAdjustedScoring && showAdjusted`. Every
effect of the toggle reads that value: `adjustedMeanMap` (moved below the gate
and built only while it is on), the two card labels and the tooltip labels. The
user's choice survives in state, but has no effect while the gate is closed.

**One deviation, stated.** The brief wrote `e.enabled`. The existing rule is
`isEventOn(e)`, where an absent `enabled` means on (REQ-D6-01). `e.enabled`
would have treated every older event as off.

**Typing.** The context types `marketEvents` as `unknown[]`, so the one read site
casts it to `MarketEvent[]`, which is what WhatIfTab writes there.
