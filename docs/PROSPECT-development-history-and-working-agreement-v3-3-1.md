## 1. What PROSPECT is

PROSPECT (Predictive Reporting Of Scenarios & Planned Execution for Commercial Trends) is a React/TypeScript subscriber forecasting application for Vodafone, built entirely through Claude Code — Jon directs, writes no application code himself. It originated in Google AI Studio, migrated to Claude due to usage limits, and was rebuilt around real IBRO data (Inflow, Base, Retention, Outflow) after initially mocking segments.

- Three-step workflow sharing state via ForecastContext: Baseline Forecast → Market Events → Actuals Review; plus Scenario Compare (own parser, never gated). Step 2/3 unlock **derives from store contents** (generation, never a save — no save action exists or ever has). The top-nav item is labelled **Overall Forecast** and targets the overall view; Step 1 is reached from the step indicator.
- Forecasting models: SES, Holt Linear, Damped Trend, true Holt-Winters (replaced a mislabelled ARIMA). Accuracy scoring: symmetric absolute percentage deviation, band position as secondary flag.
- **Base volume is never fitted or stored per month** — it is reconstructed at read time by rolling an opening stock (the seed) forward through forecast flows. The seed's known-ness is explicit (`seedBaseKnown`); an unknown seed declines the series rather than fabricating one.
- Dimensions: Customer Segment + Product/Channel/Tariff L1/L2. 7-part keys via makeForecastKey (exported once; App delegates). By ScopeDims convention 'All'/null/undefined are all wildcards, so a literal 'All' can never come from a data row.
- **Event carriers — THREE, not two** (established 2026-08-14): `MarketEvent` (Volume card AND Promotion card, discriminated by `isPromotion`; sheet Market_Events), `YieldEvent` (Value/Yield card; sheet Yield_Events), `PricingEvent` (Pricing card; sheet Pricing_Events). Each has its own state array, export sheet, and hand-rolled list table. Only MarketEvent has `campaignName`; only YieldEvent has `rollForward`; only PricingEvent has `duration`; scope dims differ per carrier (yield has no productL2 or tariff dims).
- **Cross-carrier application order is a FIXED PIPELINE BY KIND**: market events → yield events (pass 2) → pricing events (pass 3), month within. Market `sequence` is explicitly display/edit-slot only, NOT processing order (the maths is order-independent by construction); YieldEvent and PricingEvent carry no ordering field at all — creation order across carriers does not exist to be shown.
- Business users: Alessandro Russo and Marcel Wiegand. Tool is in testing, not yet UAT — numbers unused. UAT bar: Phase 3 (done), the Phase 3 walk (done), the R4/R5 arc, and the DQ import phase.
- Roadmap: Cloud Run hosting + BigQuery, AI Booster ML integration, four AI use cases; AISHA can close the loop from Actuals Review to Market Event generation via a strict event schema. AI capability parked on ai-capability branch pending prod approval.
- Deployment: nginx serves the built app, no Node server in production. server.ts is tracked in git; the exclusion lives at the Docker layer — `.dockerignore` (lines 48–49), not gitignore.

## 4. Standing rules (mirrored in EXPECTED.md / agent definitions)

- Provenance: establish any artefact's commit against HEAD before reading a number from it; fixtures arrive under new names with provenance recorded. A test artefact created against a partly-changed build is a weaker witness.
- No figure for a population you haven't opened — including error lists.
- Surface-not-store: an expected value is measured on the surface the user will look at. Siblings: state-not-transition; a correct value in a component that never renders is the same defect one level up. A spec for "the user sees X" mounts from above EVERY gate between state and X. **Corollary for gates:** a gate derives from the store, never from transient context or from which path populated a screen.
- **A spec may not feed itself the artefact under test** (trap 33).
- **A probe that MODELS the path under test inherits the modeller's assumptions — drive the real path.** Specs on file-facing paths drive the real reader/writer; round-trip checks drive the WRITER, not the reader on literal inputs.
- **Running a spec is evidence for what the spec mounts, and nothing wider** — every certificate names the boundary between what was mounted and what was read from source.
- An enumeration method is evidence about what it found, never what it missed; a text-search negative names the files its instrument covered. Agent claims get the same verification as greps.
- regression-guard classifies introduced-by-branch vs pre-existing-and-recorded; widening blast radius counts as introduced-in-effect. Only-door claims are verified over the full call-site enumeration, not sampled.
- A spec guard is verified by a planted violation or it is not verified; plants go where the heuristic is weakest; INCONCLUSIVE is a state that earns its keep. Enumeration pins are raised only AFTER the new site is classified by its own text.
- Removal test authoritative when typecheck is green. Untestable-in-place code is itself the defect — extract the seam. The rename test precedes any consumer trace.
- **Third-instance rule:** if the reason a thing is safe lives outside the thing, the next caller will not inherit it. Load-bearing invariants are *exercised* by a check at the site, not commented.
- JSON.stringify launders NaN to null. Sibling: **an exported 0 is not recoverable as absence** — known-ness needs its own column.
- Deployment "not needed" statements must be translated to a layer (repo / build / container) before anything is deleted or ignored.
- A marker is not always evidence of the thing: 'All' means column-absent in legacy imports, a leaf in unmapped dimensions; the DQ phase's mapped-dimension source of truth closes the four marker-meaning sites against one set.
- Duplicate predicates are collapsed on sight. R3 corollary: an orphan predicate computed separately by the refusal and the rows could refuse a save while displaying nothing to fix — one exported definition read by every consumer.
- Reserved decisions (CLAUDE.md): a decision stays reserved even where the answer looks self-evident; sessions HOLD and present options rather than choosing.
- **A harness noop is a declared gap that needs a source-side count guard.**
- **Nullable-under-no-strict enumerates nothing:** absence is carried where the compiler *does* look — a required flag, a named column, or the function's own name. Do not propose flipping strict on as the fix.
- **A check whose assertion doesn't mention what the function is FOR is not a check of the function** — and traps are planted on FIXES, not only on the code being fixed.
- **When a brief says "per \<skill/convention\>", the convention wins over the brief's phrasing.**
- **A check that cannot fail is worse than an absent one** (2026-08-13): it also reports the ground is covered. Style assertions pin a token that exists ONLY in the asserted state, paired with a negative assertion on the other.
- **A source-text anchor is invalidated by DUPLICATION as much as by rewrite** (2026-08-13): correctly reusing an idiom gives the anchor a second owner, and a trap deleting one site stays green on the other. Anchors on shared idioms assert **COUNTS, not presence**. Assume any reused pattern-idiom already has two owners.
- **A multi-part mutation whose cheap part succeeds reports PLANTED while the part that matters no-ops** (2026-08-13): `mutated !== base` guards against a *total* no-op and not at all against a *partial* one. Multi-part mutations verify each part landed, or are split.
- **Anchors must not pin properties they are not testing** (2026-08-13): line endings were not any anchor's claim; anchors are built in LF and every target normalised to LF before matching; the pristine snapshot is what gets restored.
- **A summariser/projection describes, never re-derives** (2026-08-14, R4 corollary of duplicate-predicates): a display surface that recomputes an outcome is a new home for the semantics and will drift; it reads stored figures.
