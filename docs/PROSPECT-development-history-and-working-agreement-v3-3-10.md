## 1. What PROSPECT is

PROSPECT (Predictive Reporting Of Scenarios & Planned Execution for Commercial Trends) is a React/TypeScript subscriber forecasting application for Vodafone, built entirely through Claude Code — Jon directs, writes no application code himself. Rebuilt around real IBRO data (Inflow, Base, Retention, Outflow).

- Three-step workflow via ForecastContext: Baseline Forecast → Market Events → Actuals Review; plus **Scenario Compare** (up to 4 session files; own parser feeding `computeScenarioForFilter` — **a SECOND ENGINE with its own blend; the only blended-ARPU computation left**). Step 2/3 unlock derives from store contents. Top-nav: **Overall Forecast** (cohort table; no chart seam).
- Models: SES, Holt Linear, Damped Trend, true Holt-Winters. Scoring: symmetric absolute percentage deviation + band position.
- **Base volume is never fitted or stored per month** — reconstructed at read time from the seed rolled through flows; `seedBaseKnown` gates; unknown seed declines. **All four per-scenario ARPUs (inflow/outflow/retention/base) ARE fitted and banded on every forecast month.**
- Dimensions: Customer Segment + Product/Channel/Tariff L1/L2; 7-part keys. A literal 'All' is a DATA VALUE (never translated — TERMBASE §5) and the wildcard in recorded scopes. **'All' has TWO representations — `null` and the string `'All'`; `cohortScope` (`WhatIfTab`) hands the engine the string, `ScenarioCompareTab` holds `null`.** ONE predicate accepts both: `eventScopeMatchesView` (`forecasting.ts`) — **11 pinned callers in `WhatIfTab`, 4 in `scenarioHelper`**, plus a structural check that the hand-rolled shape `=== 'All' || !v` occurs ZERO times in either file (a caller count cannot see a non-caller — seven copies were found after the count read green).
- **Event carriers — THREE** (`MarketEvent`, `YieldEvent`, `PricingEvent`). Pipeline order: market → yield → pricing. `YieldEventLike` carries four dims (no tariff, no productL2) — an absent dim matches.
- **How a market event reaches a view (as at `2ecdefb`):** (1) applicability — `eventScopeMatchesView`, target INTERSECTS view; (2) weighting — percentage events by `forecastCoverage` (fitted forecast at the view for the month; `null` when it cannot answer, real `0` when the target matches no populated leaf; `eventCoverage` fallback for STORED aggregates), absolute events by `eventProRataShare` under the SAME contract since `2b818ee` (`null` for no denominator, resolved to the legacy 1 explicitly at both call sites; real `0` for no populated leaf); (3) record — coverage/share 0 goes to `zeroCoverageEventIds`, not `appliedEventIds` (three readers: `Applied_Event_IDs` export column, `hasEvent` on chartData, KPI caption; `EventApplication.viewShare` carries the share separately from `sharedVolume` because magnitude-zero IS applied); the row expander reads the record, two keyed empty states.
- **Pools feed the ARPU of their own scenario (`2ecdefb`):** the Inflow event pool → Inflow ARPU (adjusted); the re-banded Retention pool → Retention ARPU (adjusted); Base takes pools only as the T+1 lag delivers them (`eventMonthIdx < idx`). ONE pool arithmetic (override, else revenue/volume, else stated rate, else baseline; size = view share, resolved for a percentage). `poolsFor` is deleted. The synthetic yield pool (built from the previous month) is a third push site, feeds no scenario term.
- **The Step-2 chart is a GRID** (`42c55ac`): MEASURE row (Volume / Revenue / ARPU) × SCENARIO pills (Inflow / Outflow / Retention / Base), **baseline SOLID / adjusted DASHED** (verified in source). Service revenue is the numerator of ARPU at every grain. Base measures carry the T+1 lag. `chartData` columns persist (`ARPU (Adjusted)` written for export compatibility; **zero readers in `src/`**). **The KPI ARPU Delta card shows FOUR per-scenario deltas** (`20799e3`, testids); absence renders an em dash, never 0.00; end-of-period, so a flow event in an earlier month reads 0 on its own flow and non-zero on Base.
- **The pricing card's Baseline ARPU (Preview AND row) is per-scenario, event-scoped** (`20799e3`, Q3 mapping in §3): `pricingBaselineArpu`, ONE definition, **exactly two callers**; sums are Σrev/Σvol never averages; absence propagates as null; the absent-row 0 fallback kept deliberately; stored rows verbatim. `resolveEventScopeForecast` remains the scope seam.
- **Churn mode (R7)** as at v3.3.6 plus D5-revised and Δ direction-of-effect; the carrier is a TARGET RATE. **Q1 (hold/revert) queued.**
- **The volume card's ARPU companion** is a rate in both amount modes; **own mode queued.**
- **Promotion card:** absolute-only volume arm; value-mix arm with padlock (`promoMixLocked`, component state, NOT persisted) and ARPU-target auto-balance (`solveForTarget`/`achievableTargetRange`, card-agnostic, unreachable is shown never clamped); pricing arm `promoPricingMode` percentage/absolute with no dilution, duration, target or applies-to fields. **No slider component exists** — two raw `<input type="range">` (Promotion `:6834`, Value `:7363`); the constraint engine (`rebalance`) is shared; the padlock is bolted on. Three amount-mode controls, none shared (two named "pricing mode" with disjoint domains); two duration controls (Pricing enum, Value `rollForward` boolean, same semantics per source). `buildPromoEvents` resolves eagerly (`:526`, `:533-535`, `:546-547`); the re-banded pool at `:1327` still reads the stored scalar; `promoMix` and band overrides are magnitude-independent.
- **Locales:** six, 856 keys each; TERMBASE governs (no "view" row); `scan-i18n --check` in the gate with a `NEVER` list (export column identifiers, justified) and the `I18N_PHASE2`/`TRANS_BACKLOG` deferral lists (never re-matched — backlog); the TS-literal rule applies to `.ts` not `.tsx` (asymmetry, backlog). `tsconfig` has NO `strict`/`strictNullChecks` — a `number | null` widening produced zero errors; the null/0 contract is held by specs alone (backlog: count the errors `strictNullChecks` would raise).

## 4. Standing rules (mirrored in EXPECTED.md / agent definitions)

*The inherited set (v3.3.8 §4, the D2-03 arc's set in v3.3.9 §4) stands in full. Minted 2026-09-03:*
- **A decision is written in full or cited by its EXPECTED.md heading — never by pointer to a superseded document.** The record is the terrain; a pointer to deleted terrain is a map of nothing.
- **A rejection carries its date and reason, and the never-re-propose list cites the entry;** a bare label sends everyone looking under the wrong word.
- **A caller count cannot see a non-caller** — a pin on callers of the one definition is paired with a structural zero-occurrence check on the hand-rolled shape. (Seven copies lived beside a green count of seven.)
- **Same lines, opposite outcomes, decided by how each caller spells the wildcard** — a copy that is right only because of its caller's representation is a defect waiting for a second caller. Retire, never repair.
- **A mutation trap is coupled to the source text of the line it guards; the traps most likely to rot are on the code most likely to change.** INCONCLUSIVE is what catches the rot (13, 115).
- **A gate is green when the suite reports.**
- **A re-point that passes with or without the defect is not made** — test the trap against the new target before moving an assertion (D3-02 stayed on Base twice, measured).
- **A fixture asserts its per-scenario bands exist before per-scenario deltas are asserted** — four em dashes pass vacuously; retention `band(0)` on every leaf reads exactly like a scoping defect at All.
- **A harness passes what the card passes** (`viewLeafForecasts` omitted → 30 not 20).
- **A guide sentence is a claim about source** and is corrected from source, not from the previous guide.
- **A report with a placeholder certifies nothing.**
