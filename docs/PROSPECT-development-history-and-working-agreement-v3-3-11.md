## 1. What PROSPECT is

PROSPECT (Predictive Reporting Of Scenarios & Planned Execution for Commercial Trends) is a React/TypeScript subscriber forecasting application for Vodafone, built entirely through Claude Code — Jon directs, writes no application code himself. Rebuilt around real IBRO data (Inflow, Base, Retention, Outflow).

- Three-step workflow via ForecastContext: Baseline Forecast → Market Events → Actuals Review; plus **Scenario Compare** (up to 4 session files; own parser feeding `computeScenarioForFilter` — a SECOND ENGINE with the only blended-ARPU computation left). Step 2/3 unlock derives from store contents. Top-nav: **Overall Forecast**.
- Models: SES, Holt Linear, Damped Trend, true Holt-Winters. Scoring: symmetric absolute percentage deviation + band position.
- **Base volume is never fitted or stored per month** — reconstructed at read time from the seed rolled through flows. **All four per-scenario ARPUs are fitted and banded on every forecast month.**
- Dimensions: Customer Segment + Product/Channel/Tariff L1/L2; 7-part keys. A literal 'All' is a DATA VALUE (never translated) and the wildcard in recorded scopes. **'All' has TWO representations — `null` and the string `'All'`.** ONE predicate accepts both: `eventScopeMatchesView` (`forecasting.ts`) — 11 pinned callers in `WhatIfTab`, 4 in `scenarioHelper`, plus a structural zero-occurrence check on the hand-rolled shape.
- **Event carriers — THREE** (`MarketEvent`, `YieldEvent`, `PricingEvent`). Pipeline order: market → yield → pricing.
- **How a market event reaches a view (as at `2ecdefb`, unchanged since):** applicability by the shared predicate (target INTERSECTS view); weighting by `forecastCoverage` for percentage events and `eventProRataShare` for absolute, both under the null/0 contract (`null` cannot answer, real `0` no populated leaf); coverage-0 events go to `zeroCoverageEventIds`, not `appliedEventIds` (three readers: `Applied_Event_IDs`, `hasEvent`, the KPI caption).
- **Pools feed the ARPU of their own scenario (`2ecdefb`):** Inflow pool → Inflow ARPU (adjusted); re-banded Retention pool → Retention ARPU (adjusted); Base only via the T+1 lag. ONE pool arithmetic; `poolsFor` deleted.
- **The Step-2 chart is a GRID** (MEASURE × SCENARIO pills, baseline SOLID / adjusted DASHED). **The KPI ARPU Delta card shows FOUR per-scenario deltas** (`20799e3`); absence renders an em dash; end-of-period, so a flow event in an earlier month reads 0 on its own flow and non-zero on Base (walked: Base +0.14 at All, flows +0.00).
- **The pricing card's Baseline ARPU is per-scenario, event-scoped** (`20799e3`): `pricingBaselineArpu`, ONE definition, exactly two callers; Σrev/Σvol never averages. `ARPU (Adjusted)` column persists with zero readers in `src/`.
- **Churn mode (R7)**: the carrier is a TARGET RATE. Q1 (hold/revert) queued.
- **The mix controls, both cards (as at `670c7c3`):** ONE slider component `MixSliderRow` (`src/components/`), zero raw `<input type="range">` in the tab (pinned); ONE target panel `MixTargetPanel`, exactly two call sites, computes nothing; `MixPctBox` (the numeric echo) holds a draft and commits on Enter/blur in all modes, Escape restores, blank is a cancel. **Padlock on both cards; lock state PERSISTS** — `mixLocked?: string[]` on `MarketEvent.promoMix` and `YieldEvent.tariffMix`, columns `Promo_Mix_Locked` / `Tariff_Mix_Locked` appended after their mix column, absence `''` never `[]`, old and malformed workbooks read as no locks. **ARPU target on both cards, draft-only** (what persists is the mix it produced). **Under an applied (reachable) target a drag re-solves the untouched unlocked sliders against the sum AND blend equations** — `rebalanceToTarget` in `mixConstraint.ts`, a sibling of `rebalance` (not widened), reached from both drag handlers through `dragUnderTarget` (exactly 2 callers); feasibility in the moved share is an interval and **the wall is its endpoint** (the slider stops, the target is never rewritten; key `whatif_mix_drag_wall`); more than two free sliders → **minimum change** (least squares, active-set for non-negativity, deterministic). Three tiers + target = one degree of freedom; + one hold = zero — **exactly determined**, rendered by `exactlyDeterminedUnderTarget` (key `whatif_mix_exactly_determined`; sliders disabled, not held; wall suppressed). `immovable` has three causes; the padlock reflects only "the user held it". Auto-lock-on-drag stays OFF and is a separate open question.
- **Promotion card:** absolute-only volume arm (percentage BUILD queued, §6 item 1); value-mix arm shares the components above; pricing arm `promoPricingMode` percentage/absolute, no dilution or duration (queued). `buildPromoEvents` resolves eagerly (`:526`, `:533-535`, `:546-547`) — the recorded order for percentage is under the EXPECTED.md heading *"Percentage on the Promotion card — declined, and the reason is the resolution model, not the interaction count"* (2026-08-02).
- **Locales:** six, parity 194/194; TERMBASE governs; `scan-i18n --check` with `NEVER` (export identifiers) and the never-re-matched `I18N_PHASE2`/`TRANS_BACKLOG` (backlog); `.ts`/`.tsx` asymmetry (backlog). `tsconfig` has NO `strictNullChecks` (backlog: count first).
- **The gate (as at `670c7c3`):** `guard-traps` reports **CAUGHT / MISSED / INCONCLUSIVE / CRASHED** — CAUGHT requires a FAIL line; a non-zero exit with none is CRASHED (three traps, 72/90/102, had printed CAUGHT by crash for their whole lives; each already had its assertion and died before `report()`). ## 4. Standing rules (mirrored in EXPECTED.md / agent definitions)

*The inherited set (v3.3.8 §4, v3.3.9 §4, v3.3.10 §4) stands in full. Minted 2026-09-03/04:*
- **Cite a decision by its EXPECTED.md heading; a line number is a courtesy that rots.**
- **A never-re-propose entry cites its heading; an entry with no recoverable reason binds nobody.**
- **The STOP diffs against BASE.** **The never-shed item is built first.** **The first brief after a decision records it.**
- **A spec that cannot finish cannot be read** — CRASHED is a spec-survival defect, never "a why nobody asserted" (all three had their assertions).
- **An instrument ships with its own positive and negative controls.** A classifier that silently degrades to "everything caught" restores the defect it was built to end, invisibly.
- **A plant is verified landed before its result is read** — `git diff` on a clean tree, a pre-plant backup otherwise; a green spec after a plant means nothing unless the plant is known to have landed.
- **A trap that cannot be planted is not written** — plant first; the brief asked for two traps that measurement proved could never fire (the two reads cover each other).
- **The gate runs serially.** **A gate is green when the suite reports.**
- **Uniqueness is a property of the trap's SUBJECT** — where the spec's subject is a pair of identical sites, the trap mutates both (global class) rather than pinning one.
- **A mounted check is the only position from which "the event never arrived" and "the engine mishandled it" look different** (D2-03) — and the only one that sees a stale closure at save (D3-04).
- **A recorded decision is not evidence the code implements it** — the settled "sum and blend" sentence had never been built on either card (D4-01).
- **The panel computes nothing; the engine decides** — `MixTargetPanel` draws what `mixConstraint.ts` hands it; a second implementation of the unreachable rule or the wall is how one card undoes a settled decision.
- **Same numbers on two cards to six decimals is either one function or one defect** — assert which.
- **A drag is continuous; typing is not** — a numeric box commits on Enter/blur; committing on keystroke applies numbers the user never asked for.
- **A guide sentence is a claim about source** — 1005 §5 described a delta that never existed; corrected from `pricingBaselineArpu`, not from the previous guide.
